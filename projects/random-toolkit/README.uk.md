# random-toolkit

[English](README.md) | **Українська**

Генератори псевдовипадкових чисел з лабораторних ASD 3-4, переписані як багаторазові **рушії**, плюс тест хі-квадрат для їх порівняння
(зокрема з `std::mt19937_64`). Це перший крок об'єднання [random-class](../random-class) і [asd-random-generators](../asd-random-generators).

| Файл | Що це |
|---|---|
| `Generators.hpp` | `rtk::ParkMiller`, `rtk::LinearCongruential<M,A,C>`, `rtk::LEcuyer` (назва з лабораторної), `rtk::BlumBlumShub<M,Bits>` |
| `ChiSquare.hpp` | `rtk::chi_square_uniform(engine, samples, bins)` - прибраний клас `test_random` |
| `BasicRandom.hpp` | `rtk::BasicRandom<Engine>` - клас `Random` з random-class, де рушій є параметром шаблону, плюс `NextBool`, `NextGaussian`, `Choice`, `Shuffle`, `GetVector`; `rtk::DefaultRandom` = `mt19937_64` |
| `main.cpp` | `random_toolkit_demo`: запускає тест для кожного генератора й показує приклад зі `std::uniform_int_distribution` |
| `random_tests.cpp` | `random_tests`: тести `BasicRandom` з усіма п'ятьма рушіями, що самі перевіряють результат |

Кожен рушій має `result_type`, `min()`, `max()` і `operator()`, тому працює зі стандартною бібліотекою:

```cpp
rtk::ParkMiller pm(7);
std::uniform_int_distribution<int> dice(1, 6);
int roll = dice(pm);
```

## BasicRandom
```cpp
#include "BasicRandom.hpp"
#include "Generators.hpp"

rtk::DefaultRandom rng;                        // mt19937_64, щоразу інші числа
int roll = rng.Next(1, 6);                     // цілі: обидві межі включено
double x = rng.Next(0.0, 1.0);                 // дійсні: [lo, hi)
bool heads = rng.NextBool();                   // NextBool(0.3) = true у 30% викликів
double h = rng.NextGaussian(170.0, 10.0);
rng.Shuffle(vec);                              // випадкова перестановка
const auto& item = rng.Choice(vec);            // випадковий елемент

rtk::BasicRandom<rtk::ParkMiller> pm(42);      // будь-який рушій з Generators.hpp, фіксований seed = відтворюваність
```
На відміну від `Random` у random-class це звичайний об'єкт (не одинак), тому кожна частина програми чи кожен потік може мати власний генератор.
Якщо межі передано навпаки, їх мовчки міняє місцями, `Next(5, 5)` повертає 5, а `NextBool` / `NextGaussian` / `Choice` кидають
`std::invalid_argument` при некоректних аргументах. Тести перевіряють усе це для кожного рушія, зокрема для дуже малих
(лінійний конгруентний генератор зі 100 значень усе одно дає правильний 64-бітний діапазон).

## Вимоги
Компілятор C++17 (MSVC 2019+, GCC, Clang) і CMake 3.10+.

## Збірка та запуск
```
cmake -S . -B build
cmake --build build
./build/random_toolkit_demo [samples] [bins]      # за замовчуванням: 100000 і 10
./build/random_tests
```
Visual Studio: `File -> Open -> Folder...`, виберіть цю папку, Ctrl+F5.

## Що показує тест (100000 чисел, 10 інтервалів, рівень 5%)
| Генератор | Результат у запуску з цього репозиторію |
|---|---|
| Парк-Міллер | PASS |
| «Л'Екюєр» (ЛКГ за модулем 2^16) | PASS |
| ЛКГ m=100, a=8, c=65 | chi2 = 0.00 - виглядає ідеально, але лише тому, що період дуже короткий, і ті самі кілька значень повторюються в рівних кількостях |
| Блюм-Блюм-Шуб, M = 2111 | FAIL - модуль закороткий |
| std::mt19937_64 | PASS |

Числа залежать від seed, використаних у `main.cpp`. Тест перевіряє лише рівномірність розподілу, а не незалежність, тому «PASS» не доводить, що генератор хороший.

## Що змінилося порівняно з лабораторними
- **Описка в оригінальному коді лабораторної:** `#define IQ 12773` - правильна константа Парка-Міллера `127773` (= IM / IA). З опискою генератор був
  сильно нерівномірним (тест хі-квадрат у цьому репозиторії відхиляє його з величезним відривом). Тут це виправлено й звірено з відомим
  еталонним значенням (10000-е число для seed 1 без маски: 1043618065).
- «Л'Екюєр» з лабораторної насправді є звичайним лінійним конгруентним генератором із константами Numerical Recipes і M = 2^16.
  Залишено під назвою з лабораторної, це описано в коді.
- Тест з лабораторної вважав кожне згенероване число «спостережуваною частотою»; новий тест робить стандартне - рахує, скільки чисел потрапило в кожен інтервал.
- Переповнення знакового цілого (невизначена поведінка в коді лабораторної) зникло: уся арифметика беззнакова / 64-бітна.
- Блюм-Блюм-Шуб тут **небезпечний** (у лабораторній був простий модуль); він лише для навчання.

## Ідеї
- Додати більше статистичних тестів (тест серій, послідовна кореляція) і пошук періоду.
- `random-class` досі має старий API одинака; `BasicRandom` - напрям, у якому він може рости.
