# Додавання нової лабораторної

[English](ADDING_A_PROJECT.md) | **Українська**

1. Створіть папку `projects/<коротка-назва>/` з файлами `main.cpp` та `CMakeLists.txt`.
   (малими літерами, англійською, без пробілів: `linked-list`, `matrix-lab`, ...).
2. Покладіть туди свої файли `.cpp` / `.h` і перелічіть їх у `CMakeLists.txt` через `add_lab(...)`.
   Кожна програма потребує **унікальної** назви цілі. Один проєкт може містити кілька програм.
3. Виберіть стандарт C++, потрібний лабораторній (`STD 11/14/17/20`, за замовчуванням 17).
4. Зберігайте вихідні файли в **UTF-8** (старі коментарі у Windows-1251 на інших системах перетворюються на сміття).
5. Замість `system("pause")` / `system("cls")` використовуйте `lab::pause()` / `lab::clear_screen()` з `common/lab_compat.h`;
   пишіть `scanf`, а не `scanf_s`; `int main()`, а не `void main()`.
6. Програми, що читають із клавіатури: покладіть приклад вводу в `tests/<назва>.in` і додайте `INPUT tests/<назва>.in`,
   інакше автоматичний тест чекатиме вічно. Програми, що ніколи не завершуються: додайте `NO_TEST`.
7. Не копіюйте `.vs/`, `Debug/`, `Release/`, `x64/`, `out/`, `*.exe`, `*.ipch` - `.gitignore` їх відфільтровує,
   але все одно перевірте `git status`.
8. Заповніть `README.md` проєкту (і `README.uk.md`) та додайте рядок до таблиці в кореневому `README.md` (і `README_UK.md`).
9. Зробіть commit і push. GitHub Actions збере кожен проєкт на Windows, Linux і macOS та запустить приклади вводу.

Кореневий `CMakeLists.txt` сам знаходить нові папки в `projects/`.

## Лабораторні лише для Windows
Усе, що потребує Windows API, Windows Forms або `graphics.h`, кладіть у `legacy-windows/<назва>/` разом з оригінальними
`.sln` / `.vcxproj`. Ці папки не збираються через CMake і CI.

## Залишати старі файли Visual Studio?
`.sln` / `.vcxproj` прив'язані до однієї версії VS (набір інструментів v142 = VS 2019, v143 = VS 2022).
Щоб проєкт працював «для всіх», основним способом збірки вважайте CMake.
